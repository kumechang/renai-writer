# SNSアカウント立ち上げ〜成長のプレイブック(汎用版)

新しいジャンルのXアカウントを立ち上げて、フォロワーを増やし、(必要なら)note などの商品に
つなげるまでの手順をまとめたものです。あるジャンルのアカウントを約1か月運用して、診断と
改善を繰り返した過程から、ジャンルに依存しない部分を取り出しています。

## このドキュメントの読み方

- **根拠の強さに注意してください。** 元になっているのは、1アカウント・約1か月・バズった返信1件
  という少ない経験です。各ルールには、根拠の強さのタグを付けています。
  - `【観測】`: このアカウントの数字で確かめられたこと(ただし1アカウントの範囲)
  - `【仮説】`: 筋は通っているが、まだ数字で確かめていないこと
  - `【一般論】`: SNS運用で広く言われていること(このアカウントでは未検証)
- ジャンル固有の体験談と、その具体的な数字は、この版から取り除いています。`【観測】`は、
  元のアカウントで確かめられたことを、ジャンルに依存しない形に直したものです。
- **「プロデューサー視点の追加アドバイス」の章**は、後から追記した部分です。
  本文の手順を、「何度もアカウントを伸ばしてきた運用者」の目線で見直しています。
- 新しいアカウントで試して、タグを更新していくのが前提です。

## 全体の流れ

| フェーズ | 目的 | 主な成果物 | 次へ進む条件 |
|---|---|---|---|
| 0 | ゴールとターゲットを決める | 戦略シート | ターゲットと約束を1文で言える |
| 1 | 市場と手本を調べる | 近いアカウントの調査、型の候補 | 当たっている型を3つ以上挙げられる |
| 2 | 受け皿を作る | プロフィール、固定投稿、導線 | 初見の人に「誰向けか・何が読めるか」が伝わる |
| 3 | 初期運用(2週間) | 返信と投稿、日次の記録 | 記録が残っている |
| 4 | 診断する | 診断メモ | 詰まっている段階を特定できた |
| 5 | 専門家の目で見直す | 修正案(優先順位付き) | 修正が反映された |
| 6 | 型を抽出して反映する | 型のライブラリ、プロンプト | コピーでなく型として反映できた |
| 7 | 計測と週次レビュー | レポート、実験 | 週次のループが回っている |
| 8 | 見直し(月次・四半期) | 戦略シートの更新 | 判断の根拠が数字で残っている |

## フェーズ0: ゴールとターゲットを決める

**目的**: 何のためにやるのか、誰に向けるのかを、最初に決める。

### やること

1. **ゴールを数字と期限で決める**
   - 例: 「3か月でフォロワー◯人」「noteの月売上◯円」「認知だけ」
   - フォロワー数を目的にするか、商品の売上を目的にするかで、必要な投稿の種類が変わる。
     両方なら、優先順位を決める
2. **ターゲットを具体的に描く**
   - 年代・性別・状況・悩み・Xを見る場面・探している情報・使う言葉
   - **「あえて外す人」も書く**(全員に向けると、誰にも刺さらない)
   - 【仮説】ペルソナは3人ほど。「保存する人」「情報収集型」「感情が揺れている人」のように、
     保存する理由が違う人を混ぜると、レビューに使いやすい
3. **約束(ポジショニング)を1文で書く**
   - 「誰が、誰に、何を約束するか」
   - 例: 「◯◯な人が、△△を、□□のやり方で解決できるようにする」
4. **発信の柱とテーマの比率を決める**(まず中心の柱を1つ、周辺は全体の1割程度から)
5. **書き手の立場と、守る線を決める**
   - 実在の書き手の体験を使うのか、考え方に絞るのか。**AIが生成する部分は、体験談を使わず、場面の
     描写・観察・考え方で書く**のを基本にする(「私もそうだった」のような作った体験談は、設定・
     返信ガイド・安全チェックのどこにも入れない)
   - 実在しない体験談や取材を、事実のように書かない(「〜な人の多くが」「〜できた人は」)
6. **ジャンル固有の安全ルールを決める**(§付録Cのチェックリスト)

### 成果物

**戦略シート**(§付録Aのテンプレート)。以降のすべてのプロンプト、レビュー、プロフィールは、
ここから導く。同じ内容を複数のファイルに別々に書かない(片方を直すと、もう片方が古くなる)。

## フェーズ1: 市場と手本を調べる

**目的**: 同じ読者に向けて、すでに何が当たっているかを知る。

### やること

1. 近いジャンルのアカウントを10〜20件集める(フォロワーが多い順でなく、**自分のターゲットが反応して
   いる順**に)
2. 伸びている投稿を各アカウント数件ずつ読み、**型**に分解する(§付録B)
   - 書き出し、場面、締め、長さ、保存・返信される理由
3. 自分が出さない領域(競合と被る、安全上避ける)を決める
4. ターゲットが実際に使っている**言葉**(悩みの言い方)を集める。検索や、返信先の投稿から拾う

### 成果物

- 手本の投稿と、その型の候補(3つ以上)
- 差別化の案(近いアカウントとの違い)

## フェーズ2: 受け皿を作る

**目的**: 返信や投稿から来た人が、フォローしたくなる状態にしておく。**先にやる**(来た人を逃さないため)。

### プロフィール `【一般論】`

- **誰向けか**、**何が読めるか**、**書き手は誰か**を入れる
- 長い説明、講義のような言葉、読者にラベルを貼る言葉は避ける
- 普段の口調と、プロフィールの口調をそろえる
- 文字数の上限(160字)に収める

### 固定投稿 `【観測】`

- **売り込みにしない。** 初めて来た人が最初に見るのが、値引き付きの宣伝だと、フォローの理由にならない
- 初見の人に、価値が1投稿で伝わるもの(チェックリスト、保存したくなる基準など)にする
- 例: 有料記事の宣伝(「リポストでお得に読める」)は、チェックリスト型の投稿に差し替える

### 導線

- 流れを決めておく: 返信・投稿 → プロフィール → フォロー → **無料の入口コンテンツ** → 有料商品
- リンクは、**売る記事ではなく、無料の入口**に向ける
- 各段に指標を置く(§フェーズ7)

### 成果物

プロフィール、固定投稿、無料の入口コンテンツ(あれば)。

## フェーズ3: 初期運用(2週間)

**目的**: 反応のデータを集める。まだ完成度を求めない。

### 運用の中心は返信 `【観測】`

立ち上げ期は、届いた表示数のほとんどが返信によるもので、自分の投稿からはフォローがほぼ生まれなかった。
立ち上げ期は、**自分の投稿を量産するより、返信に時間を使う**ほうが、届く範囲が広い。

ただし、返信の表示数は一部の当たりに大きく偏る。外れが多いのが普通で、1件ごとに一喜一憂しない。

### 返信する投稿の選び方 `【仮説】`

- 表示数がそこそこあり、**まだコメントが少ない**もの(伸びている最中に早く入る)
- ターゲットの悩みに近いもの(**プロフィールの約束とつながる話題**を優先する)
- 避けるもの: 画像・リンク先に依存して中身が分からない投稿、安全上触れない話題、
  性別・属性で二分して争っている投稿
- 自動の候補検索(キーワード検索)は、候補ゼロのまま動き続けていても気づきにくい。
  人が自分で見て選ぶほうが、当たりが多かった。**自動化した仕組みは、出力件数を監視する**

### 記録するもの(必ず最初から)

返信ごとに、後で分析できる情報を残す。

- 日時、親投稿のURL・本文
- **返信した時点の、親投稿の表示数・コメント数・経過時間**(あとから取れない)
- テーマ(柱のどれか)、使った型
- 返信文
- 結果(表示、いいね、ブックマーク、プロフィールアクセス)

加えて、**フォロワー数を毎日記録する。** `【観測】` アナリティクスの投稿別「新しいフォロー」は、
実際より大きく少なく出る。投稿別のフォロー数は信用せず、日次のフォロワー数を正とする。

### 成果物

返信ログ、日次のフォロワー数、週次のアナリティクスのCSV。

## フェーズ4: 診断する

**目的**: 「どの段階で人が落ちているか」を特定する。

### 診断の順番

次の順に見て、**最初に詰まっている段階**を直す。後ろの段階を直しても、前が詰まっていれば効かない。

| 段階 | 見る数字 | 詰まっているときの例 |
|---|---|---|
| ① 届いているか | 表示数、1件あたりの中央値 | 表示が桁違いに少ない(数十) |
| ② 反応されているか | いいね率、ブックマーク率、返信率 | 表示はあるが、いいねもブックマークもない |
| ③ プロフィールを見に来るか | プロフィールアクセス ÷ 表示数 | 反応はあるが、プロフィールに来ない |
| ④ フォローされるか | フォロワー増 ÷ プロフィールアクセス | プロフィールには来るが、増えない |
| ⑤ 導線が動くか | URLクリック、無料コンテンツの閲覧、購入 | フォローはあるが、商品につながらない |

### 診断で見る具体的な点 `【観測】`

- **投稿の中身が、その投稿だけで完結しているか。** 続きを読ませる形(途中で切る、答えを2件目に伏せる)は、
  1件目が読まれない環境では、いいねも保存もされない
- **書き出し・締めが固定化していないか。** 同じ型が続くと、タイムラインで読み飛ばされる
- **投稿の本数が多すぎないか。** 本数を減らしても成果が変わらなければ、本数は成果に効いていない
- **ブックマークがあるか。** 0件なら、保存される理由(持ち帰れる中身)が無い
- **リンクが漏れていないか。** 生成ツールの共有リンクが、投稿に混ざることがある。自動投稿は、公開前の
  チェックが必要
- **配信の問題を疑う前に、規制の有無(シャドウバンなど)を確認する。**

### 成果物

診断メモ(どの段階が詰まっているか、根拠の数字)。

## フェーズ5: 専門家の目で見直す

**目的**: 自分の視点だけでは気づけない問題を、複数の目で洗い出す。

### 専門家パネルの作り方

Claude に、次のような役を順に(または並行して)担当させる。**役ごとに見る観点を分け、同じ指摘が
重なったものを優先**する。

| 役 | 見る観点 |
|---|---|
| SNS運用のインフルエンサー | 反応・拡散・フォローにつながるか。型の固定化、1行目の強さ |
| ターゲットのペルソナ(複数) | 保存するか、しないか。保存する理由、しない理由 |
| 臨床心理士(ジャンルが人の心に触れる場合) | 読者を傷つけないか。判定・ラベル・断定、危険な話題 |
| Xの成長の実践者 | 投稿の構造、返信戦略、プロフィール |
| 商品の販売の実践者(商品がある場合) | 導線、価格、無料と有料の分け方、タイトル |
| 編集者・コピーライター | 文章の質、タイトル、読みやすさ |

### 進め方

1. 各専門家に、**現状のデータ(数字と実際の投稿)を渡して**、問題と修正案を出させる
2. 修正案を集めて、**優先順位を付ける**(効果が大きく、小さな変更で済むものから)
3. **安全面の指摘は、優先順位に関係なく、先に反映する**
4. 反映したあとの出力を、ペルソナに見せて、保存・購入の判断を確かめる(ブラインドテスト。新旧を
   ラベルなしで見せて、どちらを選ぶか)

### 反映する修正の例

- 保存される投稿の型を追加し、保存判定をレビューに組み込む(保存するペルソナが0人なら、保存型は不合格)
- 1件目だけで完結する形にする。書き出し・締めの固定化を禁止する。アカウント全体の直近の書き出しを
  生成時に見せて、重複を避ける
- 投稿本数が多すぎる場合は、減らす
- **安全ゲート**を追加する。安全違反が1つでもあれば、自動投稿でも手動承認に回す
- 記事のURLは、**許可リスト(自分の公開記事のURLパターン)に合うものだけ**を投稿に使う。リンク付き投稿の
  週あたりの上限を決める
- 売れていない有料商品は、専門家レビュー → ライターが書き直し → ペルソナの購入テスト → 編集長の最終
  レビューの順で見直す。**実在しない体験談・取材のように見える記述は、すべて直す**

### 成果物

優先順位付きの修正リストと、反映後の設定・プロンプト。

## フェーズ6: 当たった型を抽出して、反映する

**目的**: たまたま当たった投稿から、**再現できる型**だけを取り出す。

### 手順

1. 当たった投稿を、**型の動き**に分解する(§付録B)
2. 当たった理由を**仮説として**書く。「配信のされ方(親投稿が大きかった)」と「文章の力」を分けて考える
   - 例: 数字の大半が親投稿の大きさによるものなら、単独の投稿では同じ数字は出ない
3. **型だけを反映し、文面や話題をコピーしない。** 手本の文言をそのまま借りると、同じアカウントの投稿が
   テンプレに見える
4. **文型・書き出し・語尾は、毎回変える。** 型(動き)は守り、文の形は変える
5. 反映したあと、**1件の当たりに合わせすぎていないか**を確かめる。当たった話題にテーマを広げても、
   来た人がプロフィールの中心テーマの読者とは別の層だった可能性がある。比率を上げすぎず、
   フォロワーの日次推移で確かめる(【仮説】)

### 返信の型 `【仮説】`

1. **相手の言葉を拾う**(短い言い回しを「」で引用)
2. **日常の具体的な場面で描く**(五感に近い一文)
3. **誰も悪く言わない基準で閉じる**(「〜は人それぞれでも、〜な人が一番」)

さらに、プロフィールまで来てもらうために:

- **保存したくなる一行を1つ作る**(親投稿の言葉を一段ずらす、区別を言い切る)
- **丸く収めるだけで終わらない**(新しい視点を1つ足す。ただし誰も悪く言わない)
- **感想や褒め言葉で終わらせない。** いいね率の低い返信は、感想で終わっていることが多い

### 成果物

型のライブラリ、プロンプトへの反映、**返信ガイド**(Claude に渡す、単体で完結したmd)。

## フェーズ7: 計測と週次レビュー

**目的**: 数字を見て、次の1週間の実験を決める。

### 見る指標

| 指標 | 見方 |
|---|---|
| フォロワーの純増(日次) | 正とする指標。週単位で見る |
| プロフィールアクセス ÷ 表示数 | ③の段階。話題とプロフィールの一致を測る |
| フォロワー増 ÷ プロフィールアクセス | ④の段階。プロフィールの出来を測る |
| 返信の当たり率(表示1,000以上の割合) | 返信する投稿の選び方を測る |
| いいね率、ブックマーク率 | ②の段階。型の出来を測る |
| テーマ別のフォロワー増 | 柱の比率を決める材料 |
| URLクリック、購入 | ⑤の段階 |

### 週次レビューの手順(1回15分)

1. アナリティクスのCSVとフォロワー数を入れる
2. Claude がレポートを作る(増減、上位・下位の返信の分析、テーマ別、転換率、前週の仮説の判定)
3. **提案は最大3つ**(設定の変更、次週の実験)
4. 承認した分だけ、設定ファイルの変更として反映する(変更履歴を残す)

### 実験の書き方

「◯◯をすると、△△が増える(減る)」+「見る指標」+「期間」+「判定基準」を、事前に書く。後から
理由をつけて判定しない。

### 実験にできるテーマ(例)

- 柱Aの返信と柱Bの返信で、フォロワー増が違うか(テーマを返信ログに付けて集計)
- プロフィール変更(固定投稿・プロフィール文)の前後で、転換率が変わるか

### 成果物

週次レポート、実験の記録、設定の変更履歴。

週次のCSVは`npm run x-analytics:report`で集計し、各処理が動いているかは`npm run ops:health`で見る
(出力が止まった処理を早く見つけるため)。

## フェーズ8: 見直し(月次・四半期)

| 周期 | 見直すこと | 判断の材料 |
|---|---|---|
| 週次 | 戦術: 型、話題の比率、返信の選び方 | 週次レポート |
| 月次 | ターゲットと約束: 実際のフォロワーが想定と合っているか | 直近のフォロワー20人のプロフィール、ブックマークした人 |
| 四半期 | ゴールと導線: 何を目指すか、商品の売り方 | フォロワー推移、購入、導線の各段の数字 |

### 続ける/見直す/やめる基準

アカウントを始める前に、基準を決めておく。例:

- 4週間でフォロワーが目標の半分に届かない → ターゲットと約束を見直す
- 2か月で、プロフィールアクセスからの転換が下がり続ける → 受け皿(プロフィール・固定投稿)を作り直す
- 3か月で、目標の3割に届かない → ジャンルや切り口を見直すか、やめる

## プロデューサー視点の追加アドバイス

> **この章の位置づけ**: 「SNSで何度もアカウントを伸ばしてきたプロデューサー/インフルエンサー」の
> 目線で、上の手順を読んで足したアドバイスです。このアカウントの数字で確かめたものではないので、
> 基本は`【一般論】`か`【仮説】`です。試した結果で、タグを更新してください。
> Xのアルゴリズムや規約に関わることは変わりやすいので、運用前に最新の情報を確認してください。

### 総評

土台はよくできています。とくに、**①段階診断(①〜⑤)、②日次のフォロワー数を正にする、③返信を中心に置く、
④記録を最初から取る、⑤安全ゲート**は、多くのアカウントが後回しにする部分です。

伸びしろは、次の3つです。

- **当たりの打席を増やす**(どこで打つかを決める)
- **当たったときに取りこぼさない**(受け皿と、当たった直後の動き)
- **覚えてもらう**(「あの人」と思われる状態をつくる)

| 論点 | 今のプレイブック | 追加で入れたいこと |
|---|---|---|
| 打席 | 投稿単位で返信先を選ぶ | 親アカウント単位で選び、常連になる(§1) |
| 受け皿 | プロフィール+固定投稿 | 直近10件まで含めた「ショーケース」(§2) |
| 記憶 | 書き出し・締めを毎回変える | 固定する部分と、変える部分を分ける(§3) |
| 反応の種類 | いいね・ブックマーク・返信 | 共感/保存/代弁の3つに分ける。リポストを指標に入れる(§4) |
| 資産化 | 当たりを型に分解する | 返信で試し、自分の投稿で本番にする(§5) |
| 当たった後 | 記載なし | 当たった直後48時間の動き(§6) |
| リスク | 安全ゲート | バズ後の批判への対応、アカウントの保全(§7) |
| 検証 | 週次レビュー、実験の書き方 | 当たりが偏る数字での判断のしかた(§8) |
| 運用の質 | AIで生成・レビュー | 文章の均質化を防ぐ(§9)、続けられる配分(§10) |

### §1 返信は「投稿」より「アカウント」で選ぶ `【一般論】`

**見立て**: 返信の表示数は、一部の当たりに偏ります(フェーズ3)。偏る世界では、**どの親アカウントに入るか**
で打率が決まります。投稿を1件ずつ探すより、「ターゲットが集まる場所」を決めて通うほうが、再現しやすい。

**やること**

1. フェーズ1の調査から、「ターゲットの反応が厚い親アカウント」を10〜20件リスト化する。
   巨大なアカウントだけにせず、**返信欄がきちんと読まれる規模**のアカウントも混ぜる
   (大きすぎると、返信が埋もれる)
2. 同じ親アカウントに繰り返し入り、**「常連」**になる。親の著者が反応してくれると、その読者にも
   見られる機会が増える
3. 返信は、親の著者ではなく、**返信欄を読んでいる第三者**に向けて書く(多くの人は、書き込まずに眺めている)
4. 返信ログに**「親アカウント」の列**を足し、親アカウント別の当たり率を出す。リストは月1回入れ替える
5. 月次の「直近フォロワー20人」の確認(フェーズ8)で、想定外の層が混ざっていたら、その流入元の
   親アカウントを疑い、リストから外す。**最初の数十人の質**が、その後の見られ方を左右しやすい
6. 手本アカウントは、今の姿だけでなく、**フォロワーが少なかった頃の投稿と、伸び始めた転機**まで遡って
   見る(今の型は、育った後にできたもので、立ち上げ期には当てはまらないことがある)

**検証**: 4週間後、親アカウント別の当たり率と、そこから来たフォロワーの質で、リストを見直す。

### §2 プロフィールの先を整える:「直近の投稿10件」をショーケースにする `【仮説】`

**見立て**: 返信から来た人は、プロフィールを見て、**直近の投稿を数件スクロールして**フォローを決めます。
自分の投稿がほとんど届かなくても、この「決め手」としての役割は大きい。自分の投稿は、拡散のためだけでなく、
**フォローの決め手**として設計します。

**やること**

1. **プロフィール → 固定投稿 → 直近10件**の3点セットが、同じ約束を語っているかを、毎週確認する
2. 直近10件には、次を混ぜる。約束とずれた話題や、雑談、宣伝は置かない
   - 約束を示す「代表型」
   - 保存される型
   - 共感される型
3. 返信で当たった話題が、プロフィールの約束とずれている場合は、**自分の投稿には持ち込まない**
   (来た人が、別の層だった問題を避ける)
4. **5秒テスト**: 初見の人に、プロフィールと直近10件だけを見せて、「誰向けで、フォローすると何が得られるか」を
   5秒で言えるか。Claude にプロフィールと直近10件を渡して、同じ質問をしても、確認できる

**検証**: ④(フォロワー増 ÷ プロフィールアクセス)の前後比較。

### §3 「覚えてもらう」設計: 固定する部分と、変える部分 `【一般論】`

**見立て**: 本文は「書き出し・締めを毎回変える」としています(読み飛ばし対策。正しい)。ただし、
**全部を変えると、何度見ても「同じ人」と認識されません。** タイムラインで「あ、この人」と思われないと、
フォローまで進みにくい。

| 変える | 固定する |
|---|---|
| 書き出し、語尾、文型 | ①約束(何を言う人か) |
| 具体的な場面、話題 | ②視点(ものの見方のクセ) |
| | ③フォーマットの「枠」(シリーズ名、見出しの付け方、画像の雰囲気) |
| | ④口調の温度 |

**やること**

- **シリーズ名を1〜2個**作る(例: 「◯◯の言い換え」「◯◯の基準」)。増やすと散らばるので、まず1つ
- **名付け**: 現象・状態・基準に名前をつける。名前があると、引用・保存されやすい
  (名前をつけるのは、現象や基準まで。読者や第三者にラベルを貼らない。§付録C)
- **視点の一貫**: 同じテーマでも、「この人はこう見る」というクセを決めておく。立場が毎回ぶれると、
  フォローの理由が残らない

### §4 反応の種類を分ける(共感・保存・代弁)と、リポストの指標 `【一般論】`

読者がアクションを起こす動機は、おおよそ3つに分かれます。**1投稿1つに絞って**設計すると、狙いがぶれません。

| 動機 | 読者の心の動き | 主な反応 | 型の方向 |
|---|---|---|---|
| 共感 | 「それ、まさに私だ」 | いいね、返信 | 日常の具体的な場面の描写 |
| 保存 | 「あとで使いたい」 | ブックマーク | チェックリスト、基準、言い換え、手順 |
| 代弁 | 「これ、言いたかった」 | リポスト、引用 | 言語化、名付け、短い言い切り |

- **本文の指標には、リポスト・引用がありません。** フォロワーの外に広がるのは、主にリポスト・引用です。
  フェーズ7の指標に、**リポスト率(自分の投稿)**を足してください
- 代弁型の言い切りは、**根拠のある範囲**にとどめる。§付録Cの禁止(根拠のない断定、ラベル貼り)に触れない
- **1行目の型(フック)**:
  1. 具体的な場面から入る
  2. よくある言い方を「一段ずらす」
  3. 対比する(AではなくB)
  4. 問いで始める(ただし、答えは同じ投稿の中で出す。続きを読ませる形にしない)
- **3秒テスト**: タイムラインに並んだとき、1行目だけで「続きを読みたい」と思えるか。隣の投稿と、
  見分けがつくか

### §5 返信は「テスト会場」、自分の投稿は「本番」にする `【仮説】`

**見立て**: 返信は、短い時間で多くの打席に立てるので、**反応のいい言い回し・視点を見つける実験場**として優れています。
当たった視点は、自分の投稿(保存型)として、**親投稿に依存しない形で書き直す**と、資産になります。

**手順(週1回)**

1. 返信ログから、いいね率・ブックマーク率が高い返信を3件選ぶ
2. 「親投稿がなくても通じるか」を確かめる。通じなければ、場面を足す
3. **型だけ**を取り出し(§付録B)、自分の投稿にする。文面はコピーしない(フェーズ6)
4. 返信での反応と、投稿での反応を比べて記録する
5. 当たった投稿は、固定投稿・無料の入口の候補にする

**注意**: プロフィールの約束とずれたテーマは、持ち込まない(フェーズ6の手順5)。

### §6 当たった直後48時間の動き `【一般論】`

**見立て**: 当たった直後が、一番フォローされやすい時間です。本文には、この時の動きがありません。

**当たる前に準備しておく**

- プロフィール・固定投稿・直近10件が整っている(§2)
- 無料の入口コンテンツが用意できている
- 「当たったらやること」を、このリストで決めてある

**当たったら**

1. 付いたコメントに、**早く・丁寧に**返す(会話が続くと、さらに見られやすい)
2. 数時間以内に、**関連する保存型の投稿を1本**出す(来た人が、直近を見て納得できるように)
3. 表示数・プロフィールアクセス・フォロワー数を、**1〜2時間おきに記録**する(あとから取れない)
4. 数日後に、転換が悪ければ、段階診断(③・④)で原因を探す

**やらないこと**

- 慌てて、宣伝やリンクを入れる
- 当たった話題に合わせて、テーマやプロフィールを大きく変える(フェーズ6の手順5)

**記録**: 当たりごとに、§付録Bのテンプレートで型に分解し、表示のされ方(親投稿の大きさ、時間帯)も残す。

### §7 バズのリスク管理と、アカウントの保全 `【一般論】`

**見立て**: 伸びるほど、批判・誤解・引用での晒しも増えます。アカウントは、積み上げた資産です。

**やること**

- **バズる前に、対応方針を決めておく**
  - 批判や揚げ足取りには、反論しない
  - 事実の誤りの指摘は、訂正または削除を検討する
  - 攻撃的な返信は、ミュート・ブロックする
  - **安全ゲートの違反に気づいたら、すぐ削除する**(§付録C)
- **規約と自動化**: 自動投稿・自動返信・短時間の大量返信・リンクの扱いは、プラットフォームのルールや
  スパム判定に触れる可能性がある。運用前と、定期的に、最新の規約を確認する。同じ形の返信を、
  短時間に連投しない
- **基本の保全**: 二段階認証、連絡先メールの管理、投稿とフォロワー数のバックアップ(日次記録は、その一部)

### §8 実験の精度を上げる(当たりが偏る世界での判断) `【一般論】`

返信の反応は、親投稿の大きさに大きく左右されます(フェーズ6の手順2)。単純な平均では、型の良し悪しが
見えません。

- 型を比べるときは、**同じ表示数帯の親投稿どうし**で比べる(層別して比較する)
- **平均ではなく、中央値と当たり率**で見る。上位1〜2件を除いた数字も、並べて見る
- **1回の実験で変えるのは、1つだけ**
- サンプルが少ないうちは、「結論」ではなく「次の仮説」にとどめる(目安として、1条件あたり20件以上は
  欲しい。厳密な基準ではない)
- 実験は、週1〜2本まで。結果は、失敗も含めて記録する(§付録D)

---

### §9 AIで量産する場合の注意: 均質化を防ぐ `【一般論】`

**見立て**: AIの文章は、整うほど、似てきます。似た投稿が続くと、読み飛ばされます。

**やること**

- 最終出力に、**人が「一文だけ」自分の視点を足す**(体験談でなくてよい。観察・判断・好みでよい)
- 生成時に、直近の書き出しだけでなく、**直近の視点・たとえ・締めの形**も見せて、重複を避ける
- 返信には、**「この返信は、他の投稿に貼れるか?」テスト**を入れる。貼れるなら不合格。親投稿の固有の言葉を
  1つ拾って、その投稿でしか成り立たない文にする

### §10 続けるための運用(週の時間配分の例) `【仮説】`

| 作業 | 配分の例 |
|---|---|
| 返信(打席に立つ) | 5割 |
| 保存型の投稿づくり(§5) | 2割 |
| 手本の観察、ネタ集め | 1割 |
| コメントへの返信、常連づくり | 1割 |
| 分析、週次レビュー | 1割 |

(配分は例です。立ち上げ期は、返信を厚めにします。)

- **ネタ帳**をつくる: ターゲットの言葉、当たった型、保存したくなった他人の投稿を貯めておく。ネタ切れを防ぐ
- **「やらない」ことを決める**: 成果に効かなかった作業(例: 投稿本数を増やすこと)は、切る
- **停滞期の見方**: フォロワーが増えない週は、感情で戦略を変えず、段階診断(①〜⑤)で詰まりを探す。
  戦略を変えるのは、週次レビューの場だけにする

## 付録C: ジャンル別の安全チェックリスト

自動投稿や返信案の生成には、**安全ゲート**(違反が1つでもあれば、手動承認に回す)を入れる。
共通のルールと、ジャンル固有のルールを分けて書く。

### 共通

- 実在しない体験談・取材・統計を、事実のように書かない(書き手・友人・知人の体験談も作らない)
- 出典のない数値を書かない
- 「絶対に」「100%」「必ず」など、根拠のない断定を使わない
- 読者の状態を判定しない(「あなたは〜な状態だ」と決めつけない)
- 読者や第三者(性別・属性・職業の人)に、否定的なラベルを貼らない
- 回復や成果の期限を示さない
- 宣伝・フォロー依頼・リンクを、返信に入れない。生成ツールの共有リンクが混ざっていないか確認する
- 政治・宗教・差別・性的な話題・炎上目的の話題を扱わない

### ジャンル固有(例)

| ジャンル | 追加で避けること |
|---|---|
| 健康 | 診断・治療の断定。薬・サプリの効果の断言。専門家への相談を妨げる表現 |
| お金・投資 | 利益の保証。特定の銘柄・商品の推奨。リスクの隠蔽 |
| 法律・税 | 個別の事案への断定的な判断。専門家への相談を妨げる表現 |
| 育児・教育 | 他の家庭のやり方の否定。医療・発達に関する断定 |

(上の表は一般的な例です。ジャンルの規約・法令・プラットフォームのルールは、実際に確認してください。)

## 付録D: 実際にやって、うまくいかなかったこと(失敗の記録)

次の運用で同じことをしないための記録です。

1. **自動化した候補検索が、数週間、候補ゼロのまま動いていた。** 出力件数を監視しておらず、誰も気づかなかった
2. **投稿別の「新しいフォロー」を、そのまま信じかけた。** 実際より大きく少なく出る。日次のフォロワー数を正にする
3. **当たった1件に合わせて、テーマを広げすぎた。** 1件のデータで戦略を変えず、テーマ別の結果を集めてから決める
4. **手本の文言が、他の返信にそのまま移った。** 型だけを渡し、文面は渡さない。文型も毎回変える
5. **固定投稿が売り込みだった。** 初見の人には、価値が伝わる投稿を最初に見せる
6. **本数を増やせば伸びると考えていた。** 本数は成果に効かなかった。返信とプロフィールに時間を使う
7. **私(Claude)が、返信案の点数を「予測」のように扱った。** 点数は読みであって、予測ではない。数字で確かめる
8. **生成ツールの共有リンクが、投稿に混ざった。** 自動投稿には、公開前のチェックを入れる
