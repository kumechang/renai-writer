# 運用メモ(このアカウント用)

`docs/sns-growth-playbook.md`(汎用)を、このアカウントで運用するときの、具体的な手順と数字をまとめたもの。
ジャンルに依存する内容は、汎用版ではなく、ここに書く。

## 1. 週次の流れ(日曜、15〜30分)

1. アナリティクス(コンテンツ)のCSVを書き出す。アナリティクスの概要から、日ごとのフォロワー数も控える。
2. `npm run x-analytics:report -- <CSV>` でレポートを作る。見るのは次の順。
   - 返信の表示数の分布(当たり率、上位1件への集中)
   - テーマ別(「サンプル不足」「1件に集中」の表示がある行は、結論にしない)
   - 宛先アカウント別(中央値が低い宛先に、通い続ける価値があるか)
   - **昇格候補**(反応の良かった返信3件)
3. 昇格候補を、返信ガイドの「昇格モード」で、自分の保存型の投稿に書き直す(文面はコピーしない)。
4. 月曜に届く `ops-health` のレポート(各処理の出力件数、承認待ちの滞留、**直近10件の公開投稿**)を見る。
   直近10件とプロフィールを Claude に渡して、「誰向けで、フォローすると何が得られるか」を5秒で答えられるか
   (5秒テスト)を試す。
5. 提案は最大3つ。変えるのは1回に1つだけ。結果は、失敗も含めて記録する。

## 2. 返信の運用

- 返信の宛先アカウントを10〜20件、手元にリスト化する。月1回、`宛先アカウント別` の表で入れ替える。
  回数を重ねるだけでは、当たり率は上がらない(直近4週間: 宛先の表示数の中央値は、1回だけの返信が325、
  2回以上が約110)。アカウントによって、中央値は24〜1,376と大きく違う。
- 返信の話題は、プロフィールの約束(中心のテーマ)に近いものを優先する。
- 返信を書くときは、返信ガイドの「貼れるか?」テストを通す。直近の返信を数件貼って、書き出し・語尾が
  重ならないようにする。最後に、自分の一文を足す。
- 同じ形の返信を、短時間に連投しない。

## 3. 当たった直後の48時間

当たったときが、一番フォローされやすい。慌てて宣伝やリンクを入れない。

**当たる前に整えておく**
- プロフィール、固定投稿、直近10件が、同じ約束を語っている。
- 無料の入口コンテンツのリンクが、プロフィールにある。

**当たったら**
1. 付いたコメントに、早く、丁寧に返す。
2. 数時間以内に、保存型の投稿を**今すぐ1本**作る。GitHub の Actions で「X Post - Generate」を手動実行し、
   `kind` に `save_worthy` を選ぶ(ペース判定を経ずに生成される。承認モードが `auto` なら、そのまま投稿される)。
3. 表示数・プロフィールアクセス・フォロワー数を、1〜2時間おきに控える(あとから取れない)。
4. 数日後、フォロワーが増えていなければ、段階診断(プレイブックのフェーズ4)で、プロフィール以降の
   どこで落ちているかを探す。

**やらないこと**
- 当たった話題に合わせて、テーマやプロフィールを大きく変える(1件のデータで戦略を変えない)。

記録: 当たった返信は、プレイブックの付録Bで、型に分解する。親投稿の大きさと時間帯も残す。

## 4. リスク管理

- **安全ゲートの違反に気づいたら、すぐ削除する。** 公開済みの投稿は、安全チェックで不合格だったものも含めて、
  ときどき見直す。
- **承認issueの整理で、コメントを付けるときは、先頭を「承認」「却下」にしない。** 承認・却下は、コメントの
  先頭がキーワードのときだけ判定される(書き込み権限のある人のコメントに限る)。以前は、本文のどこかに
  「承認」が含まれていれば承認と判定され、整理のコメントで、古い投稿3件が公開されてしまった(2026-10)。
- 批判や揚げ足取りには、反論しない。事実の誤りの指摘は、訂正または削除を検討する。攻撃的な返信は、
  ミュート・ブロックする。
- 自動投稿・自動返信・短時間の大量返信・リンクの扱いは、Xのルールやスパム判定に触れる可能性がある。
  運用前と、定期的に、最新の規約を確認する(このメモは、規約の内容を保証しない)。
- 基本の保全: 二段階認証、連絡先メールの管理。日次のフォロワー数の記録は、バックアップの一部になる。
